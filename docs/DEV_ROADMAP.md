里程碑之外、当前代码里已经有的能力：

- **聊天多会话**：`conversations` 表 + `chat_messages.conversationId`（Room **v6**）；聊天页标题右侧的会话 chip 点开底部卡片，可切换 / 新建 / 删除会话，当前会话高亮；历史、重试、清空都只在当前会话内生效，随记检索仍是全局。旧版本消息自动归入「默认对话」，全新安装由 `RoomDatabase.Callback` 播种；新建的空会话叫「新对话 N」，第一条提问后自动改用问题摘要命名，当前会话 id 存在 `SavedStateHandle` 中，进程重建后仍会回到同一个会话
- 三个主页面（记录 / 阅览 / 聊天）装在 `HorizontalPager` 里，**左右滑即可切换**，底部导航点击也会 `animateScrollToPage`、高亮跟随当前页；右上角两个小图标：**备份与迁移** + 设置，都点开底部卡片，不占主 Tab
- **按日期导入导出**：选日期 → 导出一个 zip，**每天一个文件夹**（`notes.md` 人可读的长文本 + `analysis.md` + `media/` 原文件），`README.md` 说明格式；文件名全用 ASCII 避免跨平台解压乱码；元数据放在不可见的 HTML 注释里，Markdown 渲染时看不到，导入时用来无损还原时间/类型/媒体。导入按日期合并，本地已有记录的日期整日跳过，媒体绝对路径会重新落到本机私有目录；**旧 JSON 格式的备份仍可导入**
- **图片解析**：在随记详情点「识别图片内容」，压缩到最长边 1024 后以 `image_url` + base64 发给 `/chat/completions`（需多模态模型）
- **语音转文字**：点「转写成文字」，以 multipart 上传 `/audio/transcriptions`（独立于聊天端点的 ASR 模型，默认 `whisper-1`）；结果写回随记正文并带 `[语音转写]` 前缀，之后整理与聊天自动能读到
- **图片 / 语音各自独立的连接**：设置里两块都能单独填「接口地址 / 模型 / API 密钥」，密钥用 Keystore 分别加密。图片另有「与聊天设置相同」开关（默认开）——打开时复用聊天接口的地址和密钥、只可单独指定视觉模型；关掉才出现独立的三项。语音没单独配地址/密钥时自动沿用聊天连接、只换转写模型。`visionConnection()` / `transcriptionConnection()` 在存储层解析，`MediaUnderstandingService` 按类型取对应连接
- 应用名「个人AI笔记」；记录页参考小米笔记：大标题「随记」、日期 chip、**双列等高对齐**卡片、右下角黄色 + 悬浮按钮（点一下滚回并聚焦输入框）
- **单一输入框**：不再区分短/长笔记，去掉「短笔记」标签、放大图标和整页长笔记编辑器（`LongNoteEditor` 已删除）；一个可多行的输入框写所有内容
- **标签**：文字、图片、语音都可打标签（`captures.tags`，Room v5）；详情里用 chip 增删、有预置标签，卡片显示前两个；备份 Markdown 里「标签：#a #b」可读、HTML 注释无损还原
- **输入法布局修复**：去掉 `imePadding()` 与 `adjustResize` 的双重留白，键盘弹出时 composer 卡片不再被裁掉半截、下方不再有大片空白（已截图确认）
- 卡片和阅览页的原始随记都可以**点开整页阅览**（铺满整个屏幕，长文可滚动看全，没有「放大」按钮）；顶部返回、复制全文，下面标签、识别、编辑/删除
- 卡片与阅览列表的正文统一用 `Capture.displayText` 渲染，去掉旧长笔记写入的 `# ` 标题前缀，界面不再露出多余的 `#`
- 卡片标题统一：不再按「正文有没有换行」把首行拎出来当加粗标题（否则多行/单行卡片标题样式不一致、首行还和正文重复）；所有文字卡片一律用加粗「随记」+ 完整正文，图片/语音用各自类型标题
- **图片与语音输入**：系统文件选择器选图、应用内 `MediaRecorder` 录音（RECORD_AUDIO 权限，拒绝时退回选文件），录音时显示时长与音量波形；文件复制进应用私有目录，卡片与详情可预览 / 播放
- 自定义主题、卡片组件、阅览页 Markdown 轻渲染、系统栏 insets 处理
- 随记**编辑与删除**（两者都会连带删除当天 Markdown 与整理记录）、聊天清空、单条消息长按删除
- 自定义月历：有随记的日期打圆点，未来日期不可选
- 每日整理**一条一条**列出，点开是只读详情弹层，可单独删除且不影响原始随记；聊天消息与整理结果都不可修改
- 三种预设 AI 人格（温暖 / 简洁 / 轻快），写入系统提示词，不改变检索与引用
- **四套皮肤**（暖纸 / 薄荷 / 藕粉 / 夜色），设置里即时切换，只影响本机显示
- **随记编辑开关**：默认关闭，卡片和详情都不出现编辑入口；打开后才可改，且 `editCapture()` 有二次守卫
- 消息气泡淡入上浮、思考中三个圆点错峰呼吸动画
- 自定义自适应启动图标与一整套矢量图标（导航、发送、编辑、删除、日历、整理、会话）
- Room **v6**：`captures` / `daily_analyses` / `chat_messages` / `conversations`，含 1→2、2→3、3→4（mediaPath）、4→5（tags，默认空串）、**5→6（会话表 + 消息加 `conversationId` + 索引）** 显式迁移；媒体没识别前在 AI 请求里用 `[图片记录]` / `[语音记录]` 占位，识别后直接用正文
- **可发布 release 包**：`keystore.properties`（gitignored）+ 项目外 keystore 签名，`isMinifyEnabled` / `isShrinkResources` + R8，凭据缺失时安全回退 debug 签名并警告；`keepRules/rules.keep` 固定了按名字持久化的枚举与 Room 实体

### P0 · 功能缺口

5. **引用可追溯**：`referencedCaptureIds` 已经随消息存库，但气泡只显示日期，点不开被引用的原文。

### P1 · 质量

6. ViewModel 里的中文提示仍硬编码（保存/整理/编辑/删除/聊天的错误信息），未走 `strings.xml`。
7. `ReaderViewModel` 在 Main 线程计算 `sourceFingerprint`（SHA-256），记录量变大后应挪到 `Dispatchers.Default`。
8. 删除单条用户提问时，对应的助手回答会残留。当前约定是"只删这一条"，需要确认是否改成"删问题连带删回答"。
